# 按 sdkwork-specs 规范优化 database init 体系（deploy 模块）

## 根因（已确证）
deploy 模块首批仅 10 张表（2026-06-24），此后 25 张表（含 `deploy_dns_zone`、`deploy_certificate_version`、`deploy_certificate_identifier`、`deploy_site_binding` 等）在 07-01~07-30 分批追加时**只折叠进 baseline**（`sdkwork-deployments/database/ddl/baseline/postgres/0001_deploy_baseline.sql`），`database/migrations/postgres/` 只有 `.gitkeep`/`README`，零迁移文件。
- 旧库（anchor `deploy_site` 已存在 → `apply_baseline_if_needed_locked` 按规范语义跳过 baseline，orchestrator.rs:97-100）**永远无法获得新表** → SQLx 查询报错 → `store_error` 掩盖为 50001。
- 规范要求（DATABASE_FRAMEWORK_SPEC §6.1/§7.4）：contract 演进必须走 forward migration；已有库升级禁止重放 baseline；drift 只检测不修复（§4.2）；readiness 在 required migrations 缺失时必须失败（DATABASE_SPEC §35）。

## 修复内容（仅 deploy 模块，跨 2 个仓库）

### 1. sdkwork-deployments：补齐 forward migrations（根因修复）
- **恢复历史迁移** `database/migrations/postgres/0001_deploy_upload_session_ref.{up,down}.sql`：从 git 5926afb 原样恢复（本就是 `CREATE TABLE IF NOT EXISTS` 幂等写法），保证曾应用它的旧库 checksum 匹配；按规范 §7.2 在 `database/migrations/postgres/metadata.json` 登记 `sourcePolicy: historical-immutable`（实现时先读规范原文确认格式）。
- **新增 4 个幂等迁移**（按 baseline 追加批次分组；DDL 逐字复制 baseline 对应段落，`CREATE TABLE`→`CREATE TABLE IF NOT EXISTS`、`CREATE [UNIQUE] INDEX`→`CREATE [UNIQUE] INDEX IF NOT EXISTS`，保持与 contract/schema.yaml 一致）：
  - `0002_deploy_release_artifact.up.sql`：deploy_artifact、deploy_release
  - `0003_deploy_site_runtime.up.sql`：deploy_site_binding、deploy_site_mount、deploy_site_resource、deploy_site_revision、deploy_site_variant、deploy_site_variant_rule、deploy_web_node_target、deploy_runtime_assignment、deploy_site_target_observation
  - `0004_deploy_domain_certificate_tls.up.sql`：deploy_acme_account、deploy_certificate_challenge、deploy_certificate_distribution、deploy_certificate_identifier、deploy_certificate_order、deploy_certificate_version、deploy_dns_zone、deploy_domain_verification、deploy_listener_certificate_binding、deploy_tls_policy、deploy_tls_runtime_assignment、deploy_tls_runtime_snapshot、deploy_tls_target_observation
  - `0005_deploy_node_cluster.up.sql`：deploy_node_cluster（工作区新表）
- 每个文件带规范 §7.2 元数据头（`-- sdkwork:migration`、id、engine: postgres、module: deploy、purpose、`reversible: false`、`rollback: forward-fix`、`transactional: true`、lock、lock_timeout、statement_timeout、contract_version）；**无 down 文件**（DROP TABLE 非 data-preserving，规范 §7.1 禁止）。
- 更新 `migrations/postgres/README.md` 说明演进策略。
- 效果：新库（baseline 全建）迁移幂等跳过；旧库 migrate 补齐缺失表 → drift clean。

### 2. sdkwork-deployments：deploy database host 补 drift/readiness 检查（规范 §35）
- `crates/sdkwork-deploy-database-host/src/lib.rs` 的 `bootstrap_deploy_database`：migrate 之后加 `DriftEngine::analyze()`，error 级 drift > 0 时返回 Err 拒绝启动，错误信息提示 `pnpm db:migrate` + `pnpm db:drift:check`（完全对齐 web host 的 `crates/sdkwork-webserver-database-host/src/lib.rs:49-66`）。
- 行为变化（符合规范）：deploy schema 缺表时 gateway **启动失败并给出明确提示**，而非启动成功 + 请求 500。dev 环境 auto_migrate=true 自动补齐后启动成功。

### 3. sdkwork-deployments：暴露可复用 migrate-only 入口
- `crates/sdkwork-api-deployments-assembly/src/bootstrap.rs` 新增 `pub async fn migrate_database_from_env()`（等价 standalone-gateway 的 `run_database_migrate_only`：`set_var(SDKWORK_DATABASE_AUTO_MIGRATE=true)` + `bootstrap_deploy_database_from_env`）；`sdkwork-api-deployments-standalone-gateway` 的 db-migrate 改为复用。

### 4. sdkwork-webserver：db-migrate 覆盖 deploy 模块
- `crates/sdkwork-api-webserver-assembly/src/bootstrap.rs` 的 `migrate_database_from_env()`：先 web（现有逻辑）后 deploy（调用第 3 步新入口），与启动顺序一致（规范 §4.3 多模块按 manifest 顺序执行）。
- 效果：standalone gateway 的 `db-migrate` 子命令一键迁移 web + deploy 双模块。

### 5. 升级测试（TEST_SPEC §2.0.2.1 要求）
- 新增 `crates/sdkwork-intelligence-deploy-repository-sqlx/tests/database_upgrade_postgres.rs`（复用 `tests/common/mod.rs` 的随机 schema 隔离模式，env `SDKWORK_DATABASE_TEST_POSTGRES_URL`）：
  - **旧库升级路径**：执行完整 baseline → DROP 25 张后加表（模拟旧库，anchor 仍在）→ `LifecycleOrchestrator.init()` + `migrate()` → 断言 36 张表齐全 + `DriftEngine` error == 0
  - **新库路径**：空 schema → init + migrate → 断言全表存在 + 迁移历史 5 条（0001~0005）+ drift clean（验证迁移与 baseline 幂等共存）
- Cargo.toml 补 dev-dependencies（sdkwork-database-lifecycle / sdkwork-database-drift，按需）。

## 明确不做

- 不引入 RegistryLifecycleOrchestrator 重构
