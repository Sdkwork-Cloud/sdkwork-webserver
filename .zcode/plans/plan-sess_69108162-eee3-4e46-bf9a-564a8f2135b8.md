## 目标
在 sdkwork-deployments 中建设"宿主节点集群"管理能力：修复现有 servers 实现的问题，新增独立 admin 分包管理节点与集群。

## 现状与问题（已审查确认）
- 已有实现：deploy_server 表 → GET/POST /backend/v3/api/servers → backend SDK client.server → admin-core registry servers 源 → admin-infrastructure 分包 servers 资源页。
- 集群管理能力：不具备（无集群表/API/UI，deploy_server 无 cluster_id）。
- 问题清单：
  1. 无集群能力（核心缺口）
  2. 前端注册对话框 bodyTemplate 用 `port: 443`，契约字段是 `sshPort`（默认 22）→ 端口被丢弃，恒为 22（admin-core/src/index.tsx:47）
  3. openapi 声明 sshUser/sshKeyPath/description，但 Rust DTO 与数据库均无此字段 → 契约漂移（openapi.yaml:659 vs dto.rs:523、DDL:565）
  4. ServerResponse 管理信息不足，metadata 列从不读写
  5. 无生命周期操作：无 update/状态变更/探活，status 永远为 0
  6. 权限范围缺 deploy.servers.write（sdkwork.app.config.json），创建操作可能被令牌作用域拒绝
  7. 通用搜索框失效：registry load 忽略 query.search
  8. servers 能力挂在 admin-infrastructure，无独立管理包

## 实施步骤

### 1. 数据库（database/）
- baseline `database/ddl/baseline/postgres/0001_deploy_baseline.sql`：
  - 新增 `deploy_node_cluster`（id/uuid/tenant_id/name/description/region/status(0启用1停用)/metadata/created_at/updated_at/version，唯一 (tenant_id,name)，索引 (tenant_id,status,updated_at)）
  - `deploy_server` 增列 `cluster_id BIGINT NULL`、`node_role INTEGER DEFAULT 0`（0=宿主节点 1=边缘节点）、`ssh_user`、`ssh_key_path`、`description`，补索引
- 运行 `pnpm db:materialize:contract` 重生成 `database/contract/schema.yaml` + `table-registry.json`

### 2. 后端（crates/）
- `sdkwork-deploy-contract/src/dto.rs`：新增 NodeClusterResponse（含聚合 nodeCount）、NodeClusterPage、CreateNodeClusterRequest、UpdateNodeClusterRequest（状态/描述）；ServerResponse 增 clusterId/clusterName/nodeRole/sshUser/description；CreateServerRequest 增 clusterId/sshUser/sshKeyPath/description（与 openapi 对齐）；新增 UpdateServerRequest
- `app_ports.rs`（DeployBackendApi）：list_node_clusters / create_node_cluster / update_node_cluster；list_servers 增 cluster_id 过滤参数；update_server
- `sdkwork-intelligence-deploy-service/src/backend.rs`：实现上述方法
- `sdkwork-intelligence-deploy-repository-sqlx`：新增 `node_clusters.rs`（list/create/update + nodeCount 子查询）；`servers.rs` 读写新列 + LEFT JOIN cluster 名称 + clusterId 过滤
- `sdkwork-routes-deploy-backend-api`：`paths.rs` 增 NODE_CLUSTERS、NODE_CLUSTER、SERVER 路径；`routes.rs` 增 handlers（GET/POST /node_clusters、PUT /node_clusters/{clusterId}、PUT /servers/{serverId}、servers.list 支持 clusterId 查询）
- `sdkwork-routes-deploy-common/src/envelope.rs`：增 node_cluster_page
- `apis/backend-api/deploy/openapi.yaml`：新增上述端点与 schema（servers.create 契约修正为与实现一致）
- 运行 `pnpm api:materialize` 重生成 json 权威、route manifest（JSON+Rust）、sdkgen 输入

### 3. SDK
- `pnpm sdk:generate:backend` 重新生成 TS backend SDK（生成 client.clusters.*、扩展 client.server.*；生成产物不手改）

### 4. 前端（apps/sdkwork-deployments-pc/）
- `tools/materialize_deployments_pc.mjs`：新增 `["admin-nodes","backend-admin","nodes",{commons},null,[["clusters","Clusters","Node cluster of host nodes","deploy.clusters.read"],["nodes","Nodes","Host node inventory","deploy.servers.read"]]]`；admin-infrastructure 行移除 servers entry（仅留 nginx）
- 运行 materializer 生成新包脚手架（package.json/specs/module.ts/index.ts）
- pc app `package.json` 增依赖 `@sdkwork/deployments-pc-admin-nodes: workspace:*`；`src/App.tsx` adminModules 加入 adminNodes
- commons：`types.ts` DeploymentsResourceKey `servers→nodes` 并新增 `clusters`；`DeploymentsWorkspace.tsx` 图标映射（nodes→Server、clusters→Network）；i18n en-US/zh-CN 同步 resource.nodes/clusters、action.nodes.create（注册节点）、action.clusters.create（创建集群）、action.clusters.update（停用/启用）（两文件 key 集合必须一致）
- admin-core `src/index.tsx`：servers 源迁移为 nodes（修正 bodyTemplate 为 {name,host,sshPort:22,sshUser,clusterId,description}）；新增 clusters 源（list/create/update）
- `apps/sdkwork-deployments-pc/sdkwork.app.config.json`：accessTokenPermissionScope 增 deploy.servers.write、deploy.clusters.read、deploy.clusters.write

### 5. 验证
- `pnpm --dir apps/sdkwork-deployments-pc typecheck` 与 `test`（含 architecture-boundary 测试：新 admin 包不得引用 app/drive SDK）
- `cargo check`：sdkwork-deploy-contract、sdkwork-intelligence-deploy-service、sdkwork-intelligence-deploy-repository-sqlx、sdkwork-routes-deploy-backend-api、sdkwork-routes-deploy-common
- `pnpm api:check`（响应信封校验）、`pnpm db:validate`、openapi-materialization 契约测试

## 边界说明
- 节点探活/心跳、SSH 实际连接执行属于运行时 worker 范畴，本次仅落地数据模型与 API 契约（status 由更新操作维护），不在本次范围
- 集群管理能力：创建/列表（含节点数）/启用停用；节点管理能力：注册（归属集群）/列表/更新（归属、描述、状态）
